# g1-brainco-description: sources, licences and modelling decisions

Everything under `g1_29dof_brainco/{urdf,mjcf}` and `robot_spec.json` is generated by `build_model.py`
from the files in `sources/` and the meshes in `g1_29dof_brainco/meshes/`. `build_model.py --fetch`
re-downloads the pinned commits below and refreshes both. `sources/mesh_manifest.json` holds the SHA-256 of
every mesh.

The unitree_rl_gym copy (`~/ntu_dev/unitree_rl_gym/resources/robots/g1_description`) and ULTRA's `g1_29dof.urdf`
are an older unitree_ros revision. They differ from the pinned file only in the ankle/waist effort limits (50 N·m
and 37 rad/s there, 35 N·m and 30 rad/s now) and in the MID-360 mount (see below). ULTRA's `g1_29dof.xml` is the
vendor MJCF with collision filters and extra bodies added.

**No single official G1 29-DoF rev 1.0 + Revo2 model exists.** Unitree ships only `g1_with_brainco_hand` for the
`mode_15` G1, which has 22.5:1 hip-pitch gearing and 5010 wrist motors. Its link geometry and inertials are the same
as rev 1.0 (checked link by link). The only differences are the hip-pitch effort and velocity limits and some newer
collision meshes. It also carries the older hand URDF, which has bogus `revolute` tip joints with `lower=upper=1`.
So the build uses the rev 1.0 body and Unitree's official adapter and mount transform, with BrainCo's own current
hand description attached.

## Decisions

1. **Body = rev 1.0 URDF, unchanged**, except that the Unitree rubber hands (`*_rubber_hand` links and
   `*_hand_palm_joint`) are removed and Unitree's `<mujoco>` compiler hint is dropped.
2. **Hand mount** follows `g1_29dof_mode_15_brainco_hand.urdf`:
   - adapter: `*_wrist_yaw_link → *_base2_link` at x = 0.0415 m
   - left hand: `*_wrist_yaw_link → *_base_link` at x = 0.0591 m, rpy (−π/2, 0, −π/2)
   - right hand: same x, rpy (+π/2, 0, +π/2)

   The mount joint is renamed `*_hand_mount_joint` to avoid a clash with Revo2's own names. The Revo2 v1.0.0
   `*_base_link` frame is identical to the older hand URDF's (same finger joint origins).
3. **Hand joints (per side, 11):** 6 actuated plus 5 coupled distal joints with URDF `<mimic>`. The multipliers are
   the vendor values: thumb 1.0945, index 1.131, middle 1.267, ring 1.252, pinky 1.271. In MJCF these are
   `<equality><joint polycoef="0 k 0 0 0">`, 10 in total.
4. **Contract slot → joint mapping**, following the BrainCo docs (motor 0 is "Thumb Flex", 0–59°; motor 1 is
   "Thumb Aux", abduction/adduction, 0–90°; fingers 0–81°):

   | slot | joint | range (rad) |
   |---|---|---|
   | `thumb` | `*_thumb_proximal_joint` | 0–1.0472 |
   | `thumb_aux` | `*_thumb_metacarpal_joint` | 0–1.55334 |
   | `index`, `middle`, `ring`, `pinky` | `*_<finger>_proximal_joint` | 0–1.41 |

   The normalised command maps as `q = u · upper`.
   **Caveat:** xr_teleoperate's `robot_hand_brainco.py` / `hand_retargeting.py` send `thumb_metacarpal` as motor 0
   and normalise it by 1.52 rad. That contradicts the BrainCo docs, which make motor 0 the 59° flexion.
   xr_teleoperate's retargeting URDF (`assets/brainco_hand/`) is the older hand: finger range 1.4661,
   thumb_metacarpal 1.5184, all mimic multipliers 1.155 / 1.0.
5. **Mimic joints are unlimited in MJCF.** revo2_description's distal ranges contradict its own multipliers:
   middle 1.41 × 1.267 = 1.786 > 1.693, and likewise for ring and pinky. Limiting them would stop those fingers
   about 4° short of the vendor's 81°. The URDF keeps the vendor ranges.
6. **Static links are fused** into their moving parent: mass, COM and inertia combined exactly with the
   parallel-axis theorem. Each fused link leaves a `<site>` with the link's name, so every URDF frame stays
   available in MJCF: `imu_in_pelvis`, `imu_in_torso`, `mid360_link`, `d435_link`, `head_link`, `*_base_link`,
   `*_tip_link`, `*_touch_link`, and so on. The build uses its own URDF→MJCF converter, not MuJoCo's importer.
   `check_model.py` then compares it against MuJoCo's own URDF importer: body poses, joint axes and inertials
   agree to 1e-9.
7. **Effort limits = pinned rev 1.0 URDF**: ankles and waist roll/pitch 35 N·m. The vendor MJCF, older URDFs and
   ULTRA use 50 N·m. Unitree lowered the URDF value in commit `5ae4fa5` ("update joint limit", 2025-03-27) and did
   not update the MJCF. Applied as MJCF `actuatorfrcrange` and motor `ctrlrange`. `robot_spec.json` also records
   `effort_limit_ultra`.
8. **Armature** = ULTRA's released-policy values: 0.010178 / 0.025102 / 0.007219 / 0.00361 / 0.00425. Joint
   damping and frictionloss are 0; the vendor MJCF has none either. ULTRA's XML classes carry damping 0.05 and
   frictionloss 0.1–0.2, but ULTRA's IsaacGym training overrides them.
9. **Actuators**:
   - 29 `motor` actuators (torque) in contract order, so the sim can apply `LowCmd` (kp, kd, q, dq, tau) exactly as
     the real robot does. `ctrlrange` = ±effort.
   - Then 12 hand `position` actuators, left 6 then right 6, in slot order, named `<side>_hand_<slot>`.
     `ctrlrange` = joint range in radians, `forcerange` = URDF effort (0.5 / 1.1 / 2 N·m), `kp = effort / 0.25 rad`,
     `dampratio = 1`.
10. **Hand drive dynamics are not specified by BrainCo (ASSUMED):** finger armature 1e-3 kg·m², joint damping
    0.01 N·m·s/rad, and the kp rule above. They give stable closing at dt = 2 ms, reaching the upper limit within
    1 s. The vendor spec is ≤0.65 s for full flexion.
11. **Contacts**:
    - Robot geoms use `contype=2 conaffinity=1`: they collide with world geoms (MuJoCo default 1/1) and never with
      each other (no self-collision).
    - Soles are the vendor's 4 spheres per foot (r = 5 mm at x = −0.05/+0.12, y = ±0.025/±0.03,
      z = −0.03 in `ankle_roll_link`), class `foot`, friction 1, condim 3. They are the same in both models.
    - The full model also collides with the vendor collision set: leg, torso and head meshes, arm cylinders and
      meshes, plus the Revo2 palm and finger meshes, all as convex hulls.
    - In `fixedhands` every non-sole collision geom is kept but disabled (contype = conaffinity = 0) for MJX speed.
      Knees, torso and hands therefore pass through the floor; detect falls from base height and orientation.
12. **Fixed-hands model**: every hand joint is removed, with fingers frozen open (q = 0) and fused into
    `*_wrist_yaw_link`. Total mass and wrist subtree mass/inertia are identical to the full model.
13. **Home keyframe**:
    - Body joints are ULTRA `default_dof_pos`: legs (−0.1, 0, 0, 0.3, −0.2, 0), waist 0, arms (0, 0, 0, 0.5, 0, 0, 0).
    - Hands open.
    - Pelvis height is solved so the 8 sole spheres rest exactly on z = 0, giving z = 0.7842 m.
    - ULTRA's `g1_teacher.yaml` has **no** `default_joint_angles`. The pose lives in the python files cited above,
      which agree with unitree_rl_gym's G1 `default_angles`.
14. **Sensors** follow the unitree_mujoco G1 layout, so a unitree_mujoco-style bridge works unchanged:
    - `<j>_pos` ×29, `<j>_vel` ×29, `<j>_torque` ×29
    - `imu_quat`, `imu_gyro`, `imu_acc`, `frame_pos`, `frame_vel` at `imu_in_pelvis`
    - `secondary_imu_quat`, `secondary_imu_gyro`, `secondary_imu_acc` at `imu_in_torso`
    - ground truth: `pelvis_pos`, `pelvis_quat`, `pelvis_linvel`, `pelvis_angvel`
    - full model only: 12 `<side>_hand_<slot>_pos`
15. **MID-360 mount** comes from the pinned URDF, following Unitree's 2026-06-16 commit "fix g1 mid360_joint
    transform". It is on `torso_link` at (0.0002835, 0.00003, 0.428434), rpy (π, 0.0511, 0): **mounted upside
    down**, z-axis pointing down, 1.257 m above the floor at home. The older files (rl_gym, ULTRA) have z = 0.41618
    and an upright sensor.
16. **Camera**: MJCF camera `head_d435` sits at URDF `d435_link` (x forward, pitched down 47.6°) with
    fovy = 42°, the D435 colour vertical FOV (assumed).
17. **Timestep** 0.002 s, `implicitfast` integrator. When the model is `<attach>`ed, the parent's `<option>` wins,
    so set it there too.
18. **URDF mesh paths** are relative (`../meshes/...`): MuJoCo, pinocchio (package_dirs = urdf dir) and the Isaac
    URDF importer resolve them. `*_ros.urdf` uses `package://g1_description/meshes/...` for RViz and
    robot_state_publisher.
19. **`*_ik.urdf`** has the same links, with every hand joint made `fixed` (nq = 29). It exists because pinocchio
    3.9 loads the 10 mimic joints of the full URDF as independent joints (nq = 51). xr_teleoperate-style arm IK
    locks the 15 leg and waist joints, leaving nq = 14.
